\section{Purpose}
This living document records each step of migrating the project from ad-hoc CSV (\texttt{data.csv}) and JSON (\texttt{data.json}) storage to a structured SQLite database using the \texttt{better-sqlite3} Node.js library. It will be updated after every migration task (schema changes, data import, service refactors, etc.).

\section{Baseline State (Pre-Migration)}
\begin{itemize}[noitemsep]
  \item User session data appended to \texttt{data.csv} with 17 columns (user choices, resolutions, metadata).
  \item Aggregated score/time data persisted in \texttt{data.json} (nested objects for scores, times, precisions).
  \item No database; all queries implied linear scans / in-memory aggregation.
\end{itemize}

\subsection{Schema Defined}
Two tables established:

\paragraph{sessions}
Mirrors original CSV structure; adds surrogate primary key for internal references.
\begin{lstlisting}[language=,breaklines=true]
CREATE TABLE IF NOT EXISTS sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user TEXT NOT NULL,
  category1 TEXT,
  videoName1 TEXT,
  videoPath1 TEXT,
  resolution1 TEXT,
  category2 TEXT,
  videoName2 TEXT,
  videoPath2 TEXT,
  resolution2 TEXT,
  QO1 TEXT,
  QO2 TEXT,
  QO3 TEXT,
  QO4 TEXT,
  QO5 TEXT,
  comments TEXT,
  screenType TEXT,
  timestamp TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_sessions_user ON sessions(user);
CREATE INDEX IF NOT EXISTS idx_sessions_timestamp ON sessions(timestamp);
\end{lstlisting}

\paragraph{users}
Stores aggregate metrics previously in JSON.
\begin{lstlisting}[language=,breaklines=true]
CREATE TABLE IF NOT EXISTS users (
  pseudo TEXT PRIMARY KEY,
  totalScore INTEGER DEFAULT 0,
  totalTime INTEGER DEFAULT 0,
  sessionCount INTEGER DEFAULT 0
);
\end{lstlisting}

\subsection{Pragmas}
Enabled Write-Ahead Logging and foreign key enforcement:
\begin{lstlisting}[language=,breaklines=true]
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
\end{lstlisting}

\subsection{Verification}
Execution output confirmed creation of tables: \texttt{sessions}, \texttt{users}, plus \texttt{sqlite\_sequence} (auto-increment bookkeeping).

\section{Step 3: Data Migration (Completed)}
\subsection{Objective}
Preserve historical data by importing existing flat files into the new SQLite schema.

\subsection{Artifacts Created}
\begin{itemize}[noitemsep]
  \item Script: \texttt{db/migrate-data.js} (one-time migrator).
  \item Backups: \texttt{backups/data.csv.bak}, \texttt{backups/data.json.bak}.
  \item NPM command: \texttt{migrate:data} to run the migrator.
\end{itemize}

\subsection{What the script does}
\begin{itemize}[noitemsep]
  \item Reads \texttt{data.csv} and maps each row to the \texttt{sessions} table.
  \item Reads \texttt{data.json} and aggregates per-user totals into \texttt{users}.
  \item Wraps inserts in a single transaction; enables WAL and sets \texttt{synchronous=NORMAL} for faster batch writes.
  \item Supports a dry run via \texttt{DRY\_RUN=1} to validate counts without writing.
  \item Uses an UPSERT for users so the script can be re-run safely without duplicating rows.
\end{itemize}

\subsection{Field mapping}
\paragraph{CSV (sessions)} The following columns are mapped 1:1 from the CSV header to the table columns:
\begin{lstlisting}[language=,breaklines=true]
user, category1, videoName1, videoPath1, resolution1,
category2, videoName2, videoPath2, resolution2,
QO1, QO2, QO3, QO4, QO5,
comments, screenType, timestamp
\end{lstlisting}
If a field is missing in a row, it is inserted as NULL (except \texttt{user} and \texttt{timestamp}, which default to 'unknown' and current ISO time respectively).

\paragraph{JSON (users)} The source file combines three objects: \texttt{scores}, \texttt{times}, and \texttt{precisions}. The script builds one record per pseudo as:
\begin{lstlisting}[language=,breaklines=true]
pseudo, totalScore <- scores[pseudo]
        totalTime  <- times[pseudo]
        sessionCount <- precisions[pseudo].sessions
\end{lstlisting}
Missing values default to 0. The users table is updated with an UPSERT so totals reflect the JSON content exactly.

\subsection{How we ran it}
Backups were created first and then the migration was executed:
\begin{lstlisting}[language=,breaklines=true]
mkdir -p backups
cp data.csv backups/data.csv.bak
cp data.json backups/data.json.bak

# Preview (no writes)
DRY_RUN=1 npm run migrate:data

# Execute migration
npm run migrate:data
\end{lstlisting}

\subsection{Verification}
After the run, we verified row counts using Node with \texttt{better-sqlite3}:
\begin{lstlisting}[language=,breaklines=true]
node -e "const Database=require('better-sqlite3');\
const db=new Database('db/database.db');\
console.log('sessions:',db.prepare('SELECT COUNT(*) AS c FROM sessions').get().c);\
console.log('users:',db.prepare('SELECT COUNT(*) AS c FROM users').get().c);\
db.close();"
\end{lstlisting}
Observed on this run: \textbf{116} sessions and \textbf{29} users.

\subsection{Idempotency and safety}
\begin{itemize}[noitemsep]
  \item \textbf{Users}: UPSERT ensures re-running sets totals to JSON values rather than duplicating.
  \item \textbf{Sessions}: Designed for one-time import; re-running would re-insert sessions. Avoid re-running or add a guard file if needed.
  \item \textbf{Dry run}: Use \texttt{DRY\_RUN=1} to validate counts before writing.
\end{itemize}

\section{Step 4: Replace Data Access Layer (Completed)}
\subsection{Objective}
Eliminate runtime reliance on flat files by routing all reads/writes through SQLite while keeping existing route behavior stable.

\subsection{What changed}
\begin{itemize}[noitemsep]
  \item \textbf{SQLite-backed handlers}: \texttt{server/data/csvHandler.js} now uses SQLite instead of filesystem CSV.\
        	exttt{appendToCsv(record)} inserts into \texttt{sessions}; \texttt{readCsv()} returns rows from \texttt{sessions} shaped like CSV records. Existing services (e.g., \texttt{statsService}) continue to work unchanged.
  \item \textbf{dbService extensions}: \texttt{server/services/dbService.js} now opens the DB in read-write mode and provides new APIs: \\
        \quad \texttt{insertSession(record)}, \texttt{setScore(pseudo, score)}, \texttt{getScore(pseudo)}, \texttt{setTime(pseudo, time)}, \texttt{getTime(pseudo)}, \texttt{computeGlobalAveragePrecision()}.
  \item \textbf{Routes updated}: \texttt{server/routes/api.js} no longer writes to \texttt{data.json}. Score/time endpoints persist in \texttt{users} table; global precision is computed from \texttt{sessions}.
\end{itemize}

\subsection{Developer notes}
\begin{itemize}[noitemsep]
  \item The legacy \texttt{jsonHandler} remains for historical reference but is no longer used by updated routes.
  \item Precision-related stats are computed on demand from \texttt{sessions}; no longer stored redundantly in JSON.
  \item Existing analytics in \texttt{statsService.js} continue to operate via \texttt{readCsv()}, now SQLite-backed.
\end{itemize}

\subsection{Implementation details}
\paragraph{Files changed}
\begin{itemize}[noitemsep]
  \item \texttt{server/services/dbService.js}: switched to read-write open; added helpers \texttt{setScore}, \texttt{getScore}, \texttt{setTime}, \texttt{getTime}, \texttt{computeGlobalAveragePrecision}. Kept existing read APIs.
  \item \texttt{server/data/csvHandler.js}: replaced CSV file I/O with SQLite queries while preserving the same interface (\texttt{appendToCsv}, \texttt{readCsv}). \textbf{Note}: \texttt{appendToCsv} now wraps operations in a transaction: insert a session and upsert/increment the user's \texttt{sessionCount}.
  \item \texttt{server/routes/api.js}: removed \texttt{jsonHandler} usage for scores/times and precision average; routes now call \texttt{dbService}.
\end{itemize}

\paragraph{SQL used}
Upsert for users (create if absent, increment \texttt{sessionCount} otherwise):
\begin{lstlisting}[language=,breaklines=true]
INSERT INTO users(pseudo, totalScore, totalTime, sessionCount)
VALUES(@pseudo, 0, 0, 1)
ON CONFLICT(pseudo) DO UPDATE SET sessionCount = sessionCount + 1;
\end{lstlisting}

Set (overwrite) last score/time values for a pseudo:
\begin{lstlisting}[language=,breaklines=true]
INSERT INTO users(pseudo, totalScore, totalTime, sessionCount)
VALUES(@pseudo, @score, 0, 0)
ON CONFLICT(pseudo) DO UPDATE SET totalScore = excluded.totalScore;

INSERT INTO users(pseudo, totalScore, totalTime, sessionCount)
VALUES(@pseudo, 0, @time, 0)
ON CONFLICT(pseudo) DO UPDATE SET totalTime = excluded.totalTime;
\end{lstlisting}

\paragraph{Transaction boundary}
When recording a session (\texttt{/addUser}), we execute within a single transaction to ensure atomicity:
\begin{enumerate}[noitemsep]
  \item Insert into \texttt{sessions}.
  \item Upsert \texttt{users} row and increment \texttt{sessionCount} for that pseudo.
\end{enumerate}

\paragraph{Endpoint behavior summary}
\begin{itemize}[noitemsep]
  \item \texttt{POST /addUser}: inserts a session; auto-creates user row on first session and increments \texttt{sessionCount}.
  \item \texttt{POST /saveScore} / \texttt{GET /getScore}: store/read score from \texttt{users.totalScore}.
  \item \texttt{POST /saveTime} / \texttt{GET /getTime}: store/read time from \texttt{users.totalTime}.
  \item \texttt{GET /precision\_moyenne\_globale}: computed on demand from \texttt{sessions} (parses \texttt{QO1} vs. \texttt{resolution1/2}).
  \item Existing stats endpoints still rely on \texttt{statsService} + \texttt{readCsv()}, which now pulls from SQLite.
\end{itemize}

\paragraph{Why this was straightforward}
\begin{itemize}[noitemsep]
  \item \texttt{better-sqlite3} is synchronous and simple: it fit the existing code structure without async refactors.
  \item We preserved the \textit{shape} of CSV access by reimplementing it over SQLite, so analytics code required no changes.
  \item Upserting into \texttt{users} avoided complex branching for first-time vs returning pseudos.
\end{itemize}

\paragraph{Verification performed}
\begin{itemize}[noitemsep]
  \item Required the updated modules and booted the server to confirm no runtime errors.
  \item Queried DB summary and computed global precision via \texttt{dbService} to validate read APIs.
  \item Inserted a test session for a brand-new pseudo and confirmed: one session row exists and the \texttt{users} row is created with \texttt{sessionCount=1}.
\end{itemize}

\paragraph{Troubleshooting}
\begin{itemize}[noitemsep]
  \item If \texttt{QO1/QO2} values carry stray quotes from legacy CSV, precision may compute lower than expected; consider a one-off normalization if needed.
  \item Ensure \texttt{db/database.db} exists (run \texttt{npm run db:init}) before exercising the endpoints.
\end{itemize}
\subsection{Data repair: normalize mis-parsed pairs (Completed)}
During the CSV\,$\to$\,SQLite migration, some rows had \texttt{QO1/QO2} split across \texttt{QO1..QO4}. We added a one-off script to reconstruct proper pairs directly in the database:
\begin{itemize}[noitemsep]
  \item Script: \texttt{db/fix-qo-fields.js}
  \item Logic: load rows, detect pairs without commas, rebuild \texttt{QO1=(perceived1,perceived2)} and \texttt{QO2=(satisfaction1,satisfaction2)}, then update within a transaction.
  \item Result: majority of sessions normalized; residual quoting does not affect SQL parsing because queries strip parentheses/quotes.
\end{itemize}

\section{Step 5: Adapt the Service Layer (Completed)}
\subsection{Objective}
Stop reading all sessions in JS and delegate aggregations to SQLite using SQL (\texttt{GROUP BY}, conditional \texttt{SUM/COUNT}) for performance and correctness.

\subsection{What changed}
\begin{itemize}[noitemsep]
  \item \textbf{Refactor}: \texttt{server/services/statsService.js} now opens the DB read-only and issues direct SQL queries instead of iterating arrays from \texttt{readCsv()}.
  \item \textbf{Compatibility}: Exported function names kept to avoid breaking routes/UI; some niche functions are stubbed for later SQL ports.
  \item \textbf{Backups}: Originals saved to \texttt{backups/step5/} prior to refactor.
\end{itemize}

\subsection{Implementation details}
We use CTEs and SQLite string functions to split the stored pairs inline:
\begin{lstlisting}[language=,breaklines=true]
WITH base AS (
  SELECT resolution1, resolution2,
         TRIM(REPLACE(REPLACE(REPLACE(QO2,'"',''),'(',''),')','')) AS pair
  FROM sessions
), split AS (
  SELECT resolution1 AS resolution,
         TRIM(SUBSTR(pair,1,CASE WHEN INSTR(pair,',')>0 THEN INSTR(pair,',')-1 ELSE LENGTH(pair) END)) AS satisfaction
  FROM base
  UNION ALL
  SELECT resolution2,
         TRIM(SUBSTR(pair,CASE WHEN INSTR(pair,',')>0 THEN INSTR(pair,',')+1 ELSE LENGTH(pair)+1 END))
  FROM base
)
SELECT LOWER(satisfaction) AS satisfaction, resolution, COUNT(*) AS count
FROM split
WHERE resolution <> '' AND satisfaction <> ''
GROUP BY resolution, satisfaction;
\end{lstlisting}

User precision is computed similarly by splitting \texttt{QO1} into two perceived resolutions and comparing with \texttt{resolution1/2}:
\begin{lstlisting}[language=,breaklines=true]
WITH base AS (
  SELECT resolution1, resolution2,
         TRIM(REPLACE(REPLACE(REPLACE(QO1,'"',''),'(',''),')','')) AS pair
  FROM sessions
  WHERE LOWER(user) = LOWER(@username)
), parts AS (
  SELECT
    resolution1, resolution2, pair,
    TRIM(SUBSTR(pair,1,CASE WHEN INSTR(pair,',')>0 THEN INSTR(pair,',')-1 ELSE LENGTH(pair) END)) AS p1,
    TRIM(SUBSTR(pair,CASE WHEN INSTR(pair,',')>0 THEN INSTR(pair,',')+1 ELSE LENGTH(pair)+1 END)) AS p2
  FROM base
), metrics AS (
  SELECT
    SUM(CASE WHEN resolution1<>'' AND p1<>'' THEN 1 ELSE 0 END) AS total1,
    SUM(CASE WHEN resolution2<>'' AND p2<>'' THEN 1 ELSE 0 END) AS total2,
    SUM(CASE WHEN resolution1 = p1 THEN 1 ELSE 0 END) AS correct1,
    SUM(CASE WHEN resolution2 = p2 THEN 1 ELSE 0 END) AS correct2
  FROM parts
)
SELECT (total1+total2) AS total, (correct1+correct2) AS correct FROM metrics;
\end{lstlisting}

\subsection{Verification}
We executed small Node checks to validate shapes and counts of: user precision, global satisfaction, confusions, device and category breakdowns. Outputs matched expectations after the \texttt{QO} normalization step.

\subsection{Notes}
\begin{itemize}[noitemsep]
  \item This change removes full in-memory scans and leverages SQLite for speed and simplicity.
  \item Minor residual quoting in data is neutralized by SQL-side \texttt{REPLACE/TRIM}.
  \item Remaining detailed functions can be ported to SQL using the same pattern if the UI requires them.
\end{itemize}

npm run migrate:data
\end{lstlisting}
